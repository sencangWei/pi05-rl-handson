这是训练失败场景的中文人工恢复面板，自动开启接管录制。XYZ、旋转、夹爪和J1～J7关节按钮均继续使用。当前已经打开的旧进程不会自动加载新代码；下次启动此入口生效。每段仍需完整恢复、保存并人工审核，草稿不进入训练。

## 新录制包含什么

除原始图像、8维状态、控制帧和物理记录外，增加：

- 每控制步 `motion-编号.npz`：前后7个臂关节角/速度、双指位置/速度、世界坐标末端位置/旋转矩阵、仿真时间；原始控制向量和控制器类型。
- 关节控制另存绝对目标 `target_qpos`（弧度）。传入关节控制器的8维向量前7项是占位零值，真正目标不能用这些零值替代。
- `motion-start-编号.npz`：每个新录制或OSC续录段开始时的完整物理与控制器快照，固定MuJoCo 3.8.1、robosuite 1.4.1、NumPy 1.26.4。此次实测单份约55.5MB，保存在本机原始录制目录。
- 元数据：字段单位、关节名称、代码和文件SHA-256、控制时间线及续录段边界。OSC草稿续录时把历史物理/运动旁档复制到新目录；混合关节段仍不能通过旧OSC续录器续录。

末端FK在独立的MuJoCo数据副本中计算，不对活动仿真执行forward或刷新观测。测得的位移只是运动记录，不能直接称为等价的模型动作标签。

## 训练接口的边界

当前π0.5 LIBERO的7维动作表示末端平移3、旋转3、夹爪1，不能把它解释为7个臂关节。肘部调整时，末端可以几乎不动，但关节姿态发生明显变化。新记录会保留这个区别。

继续用末端策略时，需要验证控制器能否重现示范姿态和碰撞结果；改成关节策略时，需要相应的状态、动作头、归一化和控制器适配。此次没有实现关节策略训练，也没有证明恢复成功率提高或既有卡死解决。原始丰富记录为后续选择提供依据。
