# 人工纠错数据、动作速度与抽样比例审计

2026-10-28。结论：**暂不要求重录。没有发现人工录制转训练文件时动作缩小或错位；优先检验同一任务内纠错样本占比过高的假设。** 本轮完成只读审计和下一轮实验设计，没有启动训练、替换面板或改动模型权重。现有人工录制全部保留。

## 已确认的事实

### 1. 1630 帧的转换一致，没有把正常动作改成小动作

对六条已批准原始录制生成的八个 OSC 片段，逐帧核对原始 NPZ 与 Parquet：状态、7维动作和两路解码图像像素全部一致，物理记录的动作转换到 float32 后亦一致。原录制清单内文件、元数据、训练源码和数据清单哈希均通过。八段共1630帧，其中1612个起点可以构成训练动作窗口；非终止段尾部9个起点不采，窗口不跨关节接管边界。

这证明本次文件转换没有引入缩放、重排或一帧偏移；不等于全部人工动作在每个状态下都是最优恢复决策，也不单独证明原始相机/物理内部时序完全正确。

### 2. “不平移”多数不能当作停顿

| 指标 | 人工纠错：1630帧 | 公开同任务训练集：31条、7633帧 |
| --- | --- | --- |
| XYZ指令为零 | 585（35.89%） | 42（0.55%） |
| 上述帧中实际有旋转指令 | 405（24.85%） | 42（0.55%） |
| XYZ和旋转六维全部为零 | 180（11.04%） | 0 |
| 非零XYZ指令范数小于0.15 | 375（23.01%） | 420（5.50%） |
| 末尾重复标签 / 全部窗口标签 | 270/16120（1.67%） | 1395/76330（1.83%） |

人工位姿全零的180帧中，110帧位于夹爪开合指令变号前后各10个控制步内。最长连续位姿全零为10步，在20Hz下是**0.5秒**。夹爪仍可能运动，物理控制器也可能继续跟踪，所以这里不称“物理完全静止”。邻近开合只提示抓放阶段关联，不证明已经抓稳或松开。

普通平移指令可达0.6，精细平移常见0.1；不是整条示范被统一限制成极小步幅。0.15是诊断阈值，控制量不是米/秒。部分片段以旋转为主，其XYZ位移小不代表数据应删除。不能据此把所有零平移帧剪掉，也不能把播放视频加速当作训练标签修复。

八段中63/1612个窗口的全部10步位姿指令均为零（3.91%）。窗口平移路径明显抵消的比例为人工3/1612、公开22/7633；这只是标签诊断，模型不必平均时间维动作，亦不能排除不同状态下动作歧义。上述统计没有直接解释数分钟停滞的因果能力。

### 3. 25%纠错的总体比例，落到放碗任务已超过九成

当前混合器是1个人工槽位配3个公开回放槽位，公开回放在40任务间平衡。人工全部来自任务8。因此同一任务内的理论人工比例是：

`0.25 / (0.25 + 0.75/40) = 93.02%`

按原Torch版本、seed42、batch1、shuffle、workers0、drop_last重建采样索引：前2000次取样为人工543次、公开1457次，其中公开任务8只有33次。放碗任务的人工占比为**543/(543+33)=94.27%**。多取1次预取后543/1458，与原训练状态文件的累计计数完全一致；索引SHA见JSON。

这是固定加载器下的索引重建，原训练没有逐梯度来源日志，因此不能冒充逐梯度实录。它揭示了明显的任务内权重集中：人工的旋转、精调和开合阶段可能主导该任务的更新。**是否因此过拟合或变慢，仍需只改采样比例的对照训练证明。** 公开数据与纠错数据的起始状态和阶段分布本来不同，不能仅按零动作比例判谁优谁劣。

### 4. 一个合成训练初态无效，但六条录制起点都通过

旧训练状态库18个状态有17个通过。`train-placement_failure-init06`存在碗与桌面最大约8.51mm、与柜子最大约8.53mm穿插；后续用状态库采样或PPO前应隔离它，修复后重新审计。本轮未改写原库。

该状态**没有用于这六条人工示范**。对六条录制各自精确的首个动作前物理状态另行恢复，6/6通过同一检查：有限值、原生目标未完成、无手指接触、碗穿透不超阈值。前三条录制起点与状态库条目的哈希不同，不能只检查状态库就代表检查了原录制。

检查使用MuJoCo3.8.1、robosuite1.4.1，只恢复和forward，不下发策略动作。它只检查初始碗穿透等门，不保证整条机械臂无碰撞或后续轨迹可行。审计程序返回1正是报告上述一个无效状态，属于诊断发现，不是程序崩溃。

### 5. 关节绕障恢复尚未被当前动作契约覆盖

两条录制另有444+372=816步关节接管，原始文件完整保留。当前VLA输出是7维OSC动作，不能直接监督8维关节动作，所以这816步没有伪装成OSC标签。现有八段是接管前后的OSC片段，不能因此宣称模型已学会完整关节绕障。nullspace目标变化也没有成为策略观测。

## 下一轮：只改变抽样比例的受控实验

机器可读提案：[recovery-sampling-ablation28-plan.json](../../evidence/recovery-sampling-ablation28-plan.json)。**仅冻结提案，未实现或启动。** 它替代上一份诊断报告中继续沿用25%纠错的初步建议；新统计显示该比例在单任务内部过于集中，值得先做对照，而不是直接认定最优参数。

- 从同一父模型`multitask40_lora_v1/9999`重新分支，使用fresh AdamW、LoRA、2000次更新、batch1、seed42、lr5e-6、warmup20、官方归一化，沿用原训练其余设置。
- 仅把混合槽位从1:3改为**1个人工:39个公开回放**。保留全部人工和公开训练文件，公开仍40任务平衡；总体人工2.5%，同任务内理论人工约50.63%。2000次更新期望约50个人工与49个公开任务8窗口，不保证实际计数正好如此。该低预算实验先检验慢动作假设，不保证充分学习稀有恢复。
- 不同时剪掉抓放保持、修改动作幅度、重定时标签、改变父模型或延长控制预算，以便判断抽样的作用；记录实际梯度使用的来源计数与预取计数。
- 在已校验的12个开发初态上，与父模型和当前manual6做同状态哈希、同噪声和同控制协议对照：20Hz，预测10步执行5步，最大300步，原生放盘且无手指接触连续5步才成功。完整计入超时和失败，分别报告抓空、偏移、放偏三类及墙钟推理耗时。
- 该开发集已用过，不能称盲测。诊断通过至少要求12例成功不低于10例；在与父模型共同成功的配对中，控制步中位数不能更差，并检查每例退化，避免只挑较容易的成功子集。通过也不自动晋级：仍需事前固定旧40任务回归清单和正式效率门，再在保持封存的留出集上评测。未通过则不替换面板。

若仅调抽样无改善，再检验阶段覆盖、观测歧义及关节/OSC契约；继续增加训练步数或控制上限不能替代这些检查。目前不需要用户重新录一批随机位置。
